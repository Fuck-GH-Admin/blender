# 爱芮（Aria）双源对比：站点 ZZZ Studio vs 官模 PMX

> 取证日期：2026-11-23 · 全部结论基于实测数据，非目测。
> 站点：https://zzz-studio.app/?character=aria （用独立 Chrome 实例 + CDP 全权控制抓取）
> 官模：`/home/miku/下载/爱芮_人形_by_绝区零_23ed2fca0e5b5840055dc7766ca29a9b.zip`

---

## 0. 结论速览

1. **两边是同一套游戏资产的两个下游产物**，不是两个模型。4 张漫反射贴图**逐像素同源**（相关系数 0.994 / 1.000 / 0.979 / 0.950），面部三角数**精确相等（4228 = 4228）**。
2. **渲染参数的差距是量级级的，不是调参级的。** 站点跑的是游戏原版渲染方案（`miHoYo/Character/NapAvatarStandard` 等 4 个 shader + 5 Pass 渲染路径 + 引擎全局变量）的完整转写（7 类贴图通道 × 20 个材质 surface × 11 组 capability）；官模是 MMD 标准管线——**只有漫反射 + 16×16 色阶贴图 + 4 个参数**，法线 / matcap / 高光遮罩 / 自发光 / 面部 SDF / 发影 **全部不存在**。
3. **官模为了在 MMD 里"看起来像"，做了三件事**：① 重建 525 根 MMD 标准骨骼 + 4 链 IK；② 加 403 刚体 / 573 关节做物理；③ **把头发完整复制一份**（顶点 100% 重合）做加算叠层来伪造高光。
4. 站点的 GLB **自带 PBR 参数是占位符**（9 个材质 roughness 全是 0.5527864，specular 全是 [2,2,2]），真实外观完全来自 `contract.json` + 自定义着色器。**直接把 GLB 丢进 Blender 会得到错误的效果。**

## 2. 渲染参数对比

### 2.0 术语更正：着色器 ≠ 渲染管线

我前面写「游戏原版着色器」不够准确，这里把层级拆开。**「着色器」这个词在指 `NapAvatarStandard` 这个资产时是对的**（它是 Unity ShaderLab 的一个 `.shader` 文件，证据：契约 `evidence.shader.name` + `pathId`），但**它只覆盖下面第 1 层**：

| 层 | 内容 | 证据来源 |
|---|---|---|
| **① Shader 资产（4 个文件）** | `NapAvatarStandard`（15 surface）、`NapAvatarStandardFace`（3）、`NapAvatarStandardEye`（1）、`NapStencilShadowCaster`（1） | 契约 `evidence.shader.name/pathId` |
| **② 材质数据** | 贴图绑定、mode 变体（`e021/e035/e038/e039` 是 shader keyword 分支）、颜色值 | `contract.json` 的 surface / maps |
| **③ 多 Pass 渲染路径** | Character / Stencil / Character Light / Outline / Shadow 五遍 + 渲染状态（Cull/ZWrite/Blend/Queue/zOffset） | 契约 `sourceState`、`outline` |
| **④ 引擎全局变量** | `_UISunColor`、`_RimWidth`、`_CharacterLightTonemapParams`、`_CharacterAmbient`、`_PostOutlineTint`、`_ShadowColorFadeByZ`、`_RimGlowIntensityForChara` | 游戏**运行时脚本**灌入，不在材质里 |
| **⑤ 预烘焙几何** | 12 个描边壳顶点缓冲（stride 7 / 28,171 顶点 / 788,788 B）、面部 uv3 + 头骨 forward/right 帧 | 契约 `vertexBuffers`、`faceProfile` |

站点原话已经点明 ④ 的性质：`_PostOutlineTint`「**global engine parameter, not stored in exported data**」、`_RimGlowIntensityForChara`「global engine parameter」。所以契约里 `rim.sun=[null×5]`、`rim.width=null` 不是没分析出来，是**这些值本来就不在游戏导出的资产里**。

**准确叫法：游戏原版「材质着色器 + 多 Pass 渲染路径」，或笼统称「游戏原版渲染方案」。** 下文统一用「渲染方案」。

> 佐证：社区实现 HoyoToon 的 ZZZ shader 一个 `.shader` 文件里就是 5 个 Pass —— `Character Pass`(ForwardBase)、`Stencil Pass`(ForwardBase)、`Character Light Pass`(ForwardAdd)、`Outline Pass`(Cull Front)、`Shadow Pass`(ShadowCaster)，靠 `#pragma multi_compile _IS_PASS_BASE / _IS_PASS_LIGHT` 区分。

### 2.1 站点：游戏渲染方案的完整复刻

契约把每个材质拆成一个 "surface"，共 **20 个 surface / 9 个 GLB 材质 / 3 种 mode 码**：

| mode 码 | 用途 | surface 数 |
|---|---|---|
| `e039` | 身体 / 衣服 / 头发 / 武器 | 15 |
| `e021b` | 面部 / 眉 / 眼（SDF 分支） | 4 |
| `stencil-shadow` | 头发投影（纯模板，无颜色） | 1 |

**贴图通道共 7 类（21 个资源）**，这就是官模完全缺失的部分：

| kind | 含义 | 分辨率 | 张数 | 实际挂载的 shader 槽位 |
|---|---|---|---|---|
| `D` | 漫反射 | 2048²sRGB | 4 | `_MainTex` |
| `N` | 法线 | 1024² | 3 | `_LightTex`（RG 重建） |
| `M` | 高光/遮罩数据 | 2048² | 3 | `_OtherDataTex` |
| `A` | 附加区域遮罩 | 2048² | 3 | `_OtherDataTex2`（`.b` = 自发光 mask） |
| `C` | **MatCap 球图** | 256² | 6 | `_MatCapTex2..5` |
| `F` | **面部 SDF 光照图** | 256² | 1 | 面/眼 `_LightTex` |
| `E` | **眼部色阶 LUT** | 16² | 1 | `_EyeColorMap` |

**每材质 capability 共 11 组**：`sourceState / diffuse / normalRG / shadowBody / matcaps / wideSpecular / emission / rim / gi / sdf / eyes`

关键数值（以 body 主体 surface-0 为例，全部为契约原文）：

```
outline   : enabled=true, mode="region-map", width=1, zOffset=0.01,
            unityScale=0.01, colours[0]=[1, 0.2167, 0.2167, 1]  ← 头发/描边区域色
            data="dc80c708…"  ← stride 7 反向外扩壳顶点缓冲
lighting  : smoothness=0.05, skinMatId=0,
            shadow[0..4]  = [[0.945,0.898,0.898], [0.841,0.857,0.926],
                             [0.72,0.80,0.791],   [0.80,0.754,0.72], [0.80,0.80,0.80]]
            shallow[0..4] = [[1.00,0.961,0.949], [0.919,0.927,0.96],
                             [0.812,0.902,0.892], [0.90,0.848,0.81],  [0.90,0.90,0.90]]
            rim = { enabled=true, colors=[0.55,0.55,0.55]×5, metallic=1 }
reflection: glossiness=1, specIntensity=0.1, metallic=1,
            matcap regions 2/3/4 enabled, colorBurst=0.5/0.48/0.5
wideSpec  : glossiness=1, regions toon=0.01, modelSize=1
emission  : primary.enabled=false（该材质无自发光）
sourceState: Cull=0(双面), ZWrite=1, alphaClip=0, queue="opaque"
```

描边壳顶点缓冲共 **12 个 / 28,171 顶点 / 788,788 B**，stride 固定 7（position.xyz + normal.xyz + 描边权重），运行时强制校验 `buffer.length === position.count*7`，否则整条描边丢弃。

### 2.2 官模 PMX：MMD 的"穷版"参数

20 个材质，**参数几乎是空的**——这是 MMD 管线的上限，不是作者偷懒：

| 字段 | 取值 | 说明 |
|---|---|---|
| diffuse RGBA | 全部 `(1.000, 1.000, 1.000, 1.000)` | 20/20 一致，颜色全靠贴图 |
| specular RGB | 全部 `(0, 0, 0)` | **无高光** |
| specular power | 全部 `1` | 无意义（因为 specular 全 0） |
| ambient RGB | 全部 `(0.502, 0.502, 0.502)` | 平坦，无环境色变化 |
| edge color | 多数 `(0,0,0)`；髮/髮2/髮+ 为 `(0.494, 0.247, 0.318)`（暗发色） | |
| edge size | 0.5 或 1.0 | |
| edge 开启 | **10 / 20 材质**（颜/髮/髮2/体/裙饰1/裙饰2/体2/带/肌/肌2） | 其余关闭 |
| toon 贴图 | `toon_defo.bmp` 16×16、`skin.bmp` 32×32、`hair.bmp` 32×32 | 一共 3 张，玩具级 |
| sphere (spa) | **仅 1 个材质**：髮+ → `spa\hair_s.bmp` 256²，additive | 唯一的高光来源 |
| 双面 | 20/20 double-sided | |
| memo | 全部为空 | |

**PMX 里完全没有的东西**：法线贴图、matcap、高光遮罩、自发光、面部 SDF、发影 stencil、区域色板、色调映射曲线。

### 2.5 从 JS bundle 里挖出来的着色公式（真正的算法差异）

站点把游戏 GLSL 完整转写了。核心三处：

**① 暗部反照率塑形**（`e021ShadeAlbedo`）——头发、皮肤、其他各一套：
```glsl
// 头发：固定幂 + 轻微提亮
if (hair) return pow(max(a,0.), vec3(1.0 + 0.4*lum)) * (1.05 - 0.05*lum);
// 其他：幂指数随受光量 s 在 1.4375+0.2875*lum 与 1.0 之间插值
float d = clamp(1.0 - 3.0*(nlv - nl), 0.0, 1.0);
float g = min(2.0*d*sqrt(d), 1.0);
float s = ((nl*0.5+0.5)*g + clamp(nl,0.0,1.0)) * 0.5;
vec3  p = pow(a, vec3(mix(1.4375 + 0.2875*lum, 1.0, s)));
return mix((p+a)*0.5, p, clamp(nlv,0.0,1.0));
```
**皮肤走的是「保留原色」分支**（MMD 里 20 个材质一视同仁，这是观感差异最明显的地方之一）。

**② 角色光曲线**（`e021CharLight`，对应 `_CharacterLightTonemapParams`）：
```glsl
float lum = dot(ramp + ambient, vec3(0.212673, 0.715152, 0.072175));
float c = lum < t ? lum : m - (m - t) / ((lum - t)/(m - t) + 1.0);
return ramp * (c / (lum + 0.0001));
```

**③ 自发光区域取色**（`e039`，5 段阈值 + 2×2 超采样抗边缘）：
```glsl
int e039Region(float mb){ return mb>=0.8?0 : mb>=0.6?1 : mb>=0.4?2 : mb>=0.2?3 : 4; }
float e039Mask(float ab){
  if (ab <= 0.02) return 0.0;
  float t = clamp(1.25*(ab - 0.2), 0.0, 1.0);
  return (flags.y>0.5 && flags.z>0.5) ? (flags.w>0.5 ? t : ab) : 0.0;
}
```
还带一个 HDR 保护：颜色分量 > 1 时**不再做 sRGB 解码**（否则 91.6 会变成 45000，压缩噪声被放大成白块）。

### 2.6 站点自己标注的降级 / 未实现项

契约里 `coverage: complete 14 / partial 6 / fallback 0`，并且明文写了下面这些「不是原版」的地方——**你要对比参数时，这些是不能当基准的**：

| 项 | 站点原文 |
|---|---|
| 法线 RG 重建 | "the existing shared community adaptation, **not visual approval**" |
| 边缘光 | `sun=[null×5]`、`width=null`，reasons: "missing regional _UISunColor"、"missing _RimWidth"、**"active rim hue path unknown or unimplemented"** |

### 3.2 几何：面部一模一样，头发被复制了

**面部是精确一致的**（这是最硬的证据，说明同一份网格）：

| 部位 | GLB | PMX | 三角 |
|---|---|---|---:|
| `AriaIdol_Face` | 4,192 tri | 颜+颜2+口舌+齿+口线+白目+目+目光+目影 | 4,192 |
| `AriaIdol_Eyebrow` | 36 tri | 睫眉 | 36 |
| **合计** | **4,228** | **4,228** | **完全相同** |

**头发被完整复制了一份**（已用顶点坐标集合验证）：

| PMX 材质 | 三角 | 顶点 | 贴图 / spa | 与誰重合 |
|---|---:|---:|---|---|
| 髮 | 3,013 | 2,133 | 髮.png / toon=hair.bmp | — |
| 髮2 | 4,722 | 3,501 | 髮.png / toon=hair.bmp | 与髮不重合（被拆成两段） |
| **髮+** | **7,735** | **5,634** | **sp.png / spa=hair_s.bmp (additive)** | **100% 覆盖 髮 的顶点，100% 覆盖 髮2 的顶点** |

即：**髮+ 是 (髮 + 髮2) 的完整副本**，用 additive 球面贴图叠在正常头发上，纯粹是为了伪造游戏里的发丝高光/通透感。这一项就多出 7,735 三角（占全模型 16.2%），也解释了为什么 PMX 的三角数反而比 GLB 多。

> 结论：47,734 − 7,735 = 39,999，与 GLB 角色本体 38,591 相差 1,408，属重导出时的顶点分裂/接缝差异。

### 3.4 物理：从零到 403 刚体

GLB 完全没有物理。PMX 新增：

- **403 刚体 / 573 关节**
- **366 根动态骨骼**（受物理驱动），另 23 根只挂静态跟随刚体
- 覆盖：头发（`Ctr_F_Hair_A..E`、`Ctr_L/R_Hair_A..C`，每节还带 `錘` 重物）、蝴蝶结（`Bowknot` / `BowknotF`）、领结（`Bowtie`）、鞋（`Ctr_L/R_Shoe_01..03`）
- 389/525 根骨骼至少挂 1 个刚体

implication：如果你只想复刻**外观**，这套物理是纯负担（多余 403 刚体 / 573 关节 / 366 动态骨骼）；但如果你要**动态**，这是官模相对站点唯一的优势。

## 4. 如果你要在 Blender 里复刻站点效果

1. **别指望 GLB 自带的 PBR 参数**：9 个材质 `roughnessFactor` 全是 `0.5527864`、`specularColorFactor` 全是 `[2,2,2]`、`emissiveFactor` 有 4 个是 `[1,1,1]` / 1 个暖灰 `[0.151,0.140,0.140]` / 4 个干脆没有 —— 这些是导出占位，和真实自发光无关。真实外观 = `contract.json` + 自定义着色器。
2. 站点用的是**反向外扩壳描边**（不是 Blender 的 Solidify + 法线翻转的常规做法）：数据在 12 个 `generated_*.bin` 里，每条顶点 7 float，运行时要求缓冲长度严格等于 `position.count*7`。
3. 面部必须用 **SDF**（`F` 类 256² 图 + TEXCOORD3 面部 UV + 头骨 forward/right 帧 + `color_1` 顶点色）才能出游戏那种脸——用 toon 贴图糊不出来。
4. **暗部塑形分三套**（头发 / 皮肤 / 其他），皮肤是「保留原色」，这点最容易做错。
5. 官方 MMD 包 readme 明确：**禁止二次配布、禁止商业用途、禁止拆件用于改造其他模型**。要发布对比图/二创请自行确认授权。

### HoyoToon 的 ZZZ 分支具体有什么（已下载核对 commit `d9e5ca2`）

**有的**，而且把贴图通道语义写成了文档（这部分比我反推的更权威）：

- `_MaterialType` 枚举 = `Base / Face / Eye / Shadow / Hair / EyeHighlight / EyeShadow`（7 型，对应站点的 mode 码体系）
- `_LightTex` 说明：**面部** R = SDF、G = 脸颊/鼻高光、B = 描边阈值（1.7 后移入顶点色）、A = 下巴下 AO；**身体/头发** R、G 是法线，G 兼作阴影图（对应 `_N` 后缀贴图）
- `_OtherDataTex` 说明：R = 材质 ID、G = 金属度、B = 高光遮罩（头发高光区）、A 未用（对应 `_M` 后缀）
- `_OtherDataTex2` 说明：R = 透明、G = 平滑度、B = **自发光遮罩**（对应 `_A` 后缀）
- 描边：`_OutlineWidth`、`_OutlineZOff`、**5 组 `_OutlineColor1..5` + `_OutlineHue1..5` + `_OutlineMaskSource`** —— 与站点契约的「5 区域描边色」完全对应
- 5 个 Pass 俱全（见 §2.0 佐证）

**没有的**（我 grep 确认零命中，正是站点比它新的部分）：

| 缺失项 | 说明 |
|---|---|
| `e039` 区域自发光（5 段阈值 0.8/0.6/0.4/0.2 + 2×2 超采样） | 站点有完整转写 |
| `_CharacterLightTonemapParams` / `_CharacterAmbient` | 角色光曲线，站点有 |
| `_PostOutlineTint` / `_Post*Tint` | 输出级调色，站点有 |
| `_ShadowColorFadeByZ` | 近景调色→远景恢复，站点有 |
| `_RimGlowIntensityForChara` / `wideSpecular` / GI | 站点有（rim/GI 标注为降级） |
| 预烘焙 stride-7 描边壳顶点缓冲 | HoyoToon 在 vertex shader 里实时法线外扩；站点用预烘焙权重 |

### 所以「要不要自己做一个」

三条路线，代价差别很大：

- **A. 给 PMX / MMD 用** → 打底用 **Zenlight**（MME），但它 2024-07 就停在较老版本，`e039` / CharCurve / Post*Tint 都得自己补 HLSL。MME 生态限制多（无 GBuffer、无自定义 stencil 跨 mesh）。
- **B. 给 Blender 用** → HoyoToon-Blender 是 **Goo Engine**（非官方 Blender 分支）的 shader graph，且作者明说不支持 MMD 变体。要转到标准 Blender 等于重写 node group。
- **C. 产出独立的参考实现（不绑引擎）** → 这个最有性价比，而且**素材已经在我手上**：契约给了完整参数结构（20 surface × 11 capability），我从站点 bundle 里抽出了 88 段 GLSL 原文（含 `e021` 肤色/头发/其他三套暗部塑形、`e039` 区域自发光、`e021CharLight` 色调映射曲线、描边壳、发影）。可以整理成一份**带注释的 GLSL 参考实现 + 参数表**，再附 Blender node group 的等价接法。
