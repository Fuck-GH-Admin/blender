# GLB 原始导入发白：材质节点与 UV 诊断

日期：2026-11-25  
样本：`04_站点镜像/models/aria/model.glb`  
契约：`04_站点镜像/contracts/00c580250fd8f42691f75cab6fbea3d5c45760f9f84bddc861e271ccbe152072.json`  
诊断环境：Blender 5.3.0，GitHub Actions Ubuntu Runner；本轮只做导入诊断，不涉及本地 GPU。

## 结论摘要

原始 GLB 的漫反射贴图并非空白或缺失。当前 Blender glTF 导入结果中，Image Texture 的 `Vector` 输入没有连接 UV 节点；尽管每个主体网格都有正常的 `UVMap`，贴图采样仍会退回默认 Generated 坐标。这是原始 GLB 预览发白的首要可验证原因。

此外，导入材质还保留了统一的 `Metallic=1.0` 与 `Roughness=0.5527864`。这组值与材质契约的真实通道信息不匹配：M 贴图另行提供区域 / 金属度 / 高光遮罩。导入后的 9 个材质全部显示为 `BLENDED`，而契约中主体大部分为 `opaque`，只有眼睛材质为 `blended`。

## 实测证据

### 1. 网格与 UV

- 原始 GLB 导入得到 17 个 Mesh 对象、9 个材质。
- 去除武器 / FX / HairShadow 后，角色主体保留 5 个 Mesh。
- 这 5 个主体网格均有 `UVMap`，UV 范围约在 0–1。
- 原始 GLB 导入材质的 Image Texture 节点没有连接 `Vector` 输入；材质节点树中没有对应的 UV / Texture Coordinate 节点连接。

### 2. 内嵌 D 贴图不是空白

Blender 5.3.0 对内嵌图像进行每张 2048 个均匀抽样像素的统计。以下为 RGB 均值（非全像素精确均值）：

| 内嵌图像 | 尺寸 | RGB 抽样均值 | 结论 |
|---|---:|---:|---|
| `AriaIdol_Body_1_D` | 2048×2048 | 0.730 / 0.726 / 0.723 | 存在明显颜色变化 |
| `AriaIdol_Body_2_D` | 2048×2048 | 0.517 / 0.409 / 0.422 | 有粉色 / 暖色信息 |
| `AriaIdol_Face_D` | 2048×2048 | 0.486 / 0.425 / 0.409 | 有肤色信息 |
| `AriaIdol_Weapon_D` | 2048×2048 | 0.274 / 0.274 / 0.274 | 灰度资源 |

因此不能把问题归因于“GLB 没有贴图”或“内嵌贴图全白”。

### 3. 原始材质节点结构

主体原始材质的关键链路为：

```text
Image Texture.Color ─┐
                     ├─ Mix (RGBA / MULTIPLY / Factor=1) ─ Principled.Base Color
Attribute.Color ────┘

Image Texture.Alpha ─┐
                     ├─ Math(MULTIPLY) ─ Principled.Alpha
Attribute.Alpha ─────┘
```

- Mix 节点的 Factor 为 1，模式为 MULTIPLY；不是 Factor=0 导致的纯顶点色输出。
- Image Texture 的 Vector 输入没有连接，因此未明确使用网格的 UVMap。
- Principled Base Color 确实接到了 Mix 输出；所以当前优先修复的是纹理坐标，而不是重新接 Base Color。

### 4. 导入材质状态与契约不一致

原始导入后，主体材质 Principled 参数普遍为：

- Metallic：1.0
- Roughness：0.5527864
- Surface Render Method：BLENDED

契约 `capabilities.sourceState` 则显示：

- 主体、裙装、脸、眉毛、头发等大部分材质的 queue 为 `opaque`；
- `MAT_AriaIdol_Eye` 的 queue 为 `blended`；
- `Cull` 同时存在 0 和 2，不能统一设为双面 / 不剔除；
- `_OtherDataTex`（M）独立存在，不能把 glTF 导入的统一 Metallic=1 当作真实金属度贴图。

参考：`03_EEVEE_Cycles/MAPPING.md` 中明确提醒 GLB 的统一 roughnessFactor 是导出占位值，不应照抄；contract 的 M 贴图则包含区域、金属度和高光遮罩数据。

## 已实施的对照修复

在隔离分支 `ops/aria-blender-transfer-20261124` 增加 `glb_uvfix` 条件：

1. 对每个导入的 Image Texture，若 Vector 未连接，则显式连接 `Texture Coordinate.UV`（UV0）。
2. 根据 contract 的 `sourceState.Cull` 恢复背面剔除；Cull=0 不剔除，Cull=2 剔除背面。
3. queue=opaque 的材质设为 DITHERED 并断开 Alpha 混合；queue=blended 的眼睛材质保留 Alpha 链路。
4. 将 GLB 导入的 Metallic=1 占位值置为 0，并使用按材质族区分的基础 Roughness。
5. 保留原始 GLB 导入条件作为对照；保留外部 D/N 重建条件作为另一条独立路线。

这不是完整游戏材质复刻。它只验证 UV、材质状态与占位 PBR 参数修复的影响。
